# Prediction interface

Bilingual (Spanish / English) web app for the three winning models of the
study. The language switch is at the top right; the choice is remembered and
defaults to the browser language.

| Target | Model | Exported from | Output |
|--------|-------|---------------|--------|
| BMWP/Col | ε-SVR (RBF), predictor: hardness | `models/svr_bmwp.pkl` | Value (0–120), Roldán class, ± MAE band |
| Perlidae | Fuzzy Mamdani (Approach C), predictors: turbidity, BOD₅, TDS | `models/fuzzy_perlidae.pkl` | Presence / absence, fuzzy output, or *Undetermined* if no rule fires |
| Helicopsychidae | Logistic regression, predictor: flow rate | `models/lr_helicopsychidae.pkl` | Presence / absence + probability |

## How it works

GitHub Pages is static, so inference runs in the browser:

```
notebooks ──► models/*.pkl ──► export_static_models.py ──► static/data/models.json ──► static/js/engine.js
                                       └──► tests/parity_cases.json ──► tests/test_parity.js
```

- `engine.js` re-implements the three models from their parameters: RBF-kernel
  SVR with standard scaling, logistic regression, and Mamdani inference with
  scikit-fuzzy's exact semantics (min AND, max accumulation, centroid
  defuzzification on the cut-refined output universe).
- `test_parity.js` compares the engine with the Python models on 120 random
  in-range inputs and fails above 1e-6 (observed max error < 1e-7).
- `i18n.js` holds all UI strings in both languages; static text is tagged with
  `data-i18n` attributes and dynamic text uses `I18N.t(key)`. Numbers are
  formatted per locale.

## Run locally

```bash
# Static site (what GitHub Pages serves)
python -m http.server 8000 --directory Interface        # http://localhost:8000

# Flask reference server: same page + Python models at /api/models, /api/predict
pip install -r Interface/requirements.txt
python Interface/app.py                                  # http://localhost:5000
```

Opening `index.html` directly (`file://`) will not work because the page
fetches `static/data/models.json`.

## After retraining a model

```bash
python Interface/export_static_models.py   # refresh models.json and parity cases
node Interface/tests/test_parity.js        # must report that all cases match
```

Commit the updated `models.json` and `parity_cases.json`; the GitHub Actions
workflow re-runs the parity test and redeploys.

## Deployment

`.github/workflows/pages.yml` publishes `index.html` and `static/` on every push
to `main` that touches `Interface/`. One-time setup in the repository:
*Settings → Pages → Build and deployment → Source: GitHub Actions*.

## Layout

```
Interface/
├── index.html
├── static/
│   ├── css/style.css            # Liquid-glass design (frosted panels, waves, bubbles)
│   ├── js/engine.js             # Model inference (browser + Node)
│   ├── js/i18n.js               # ES / EN strings and language switch
│   ├── js/app.js                # UI: cards, sliders, results
│   └── data/models.json         # Generated by export_static_models.py
├── export_static_models.py
├── tests/{test_parity.js,parity_cases.json}
├── app.py                       # Flask reference server
└── requirements.txt             # Flask server + exporter dependencies
```
